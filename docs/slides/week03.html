Wide vs. Long Data

bea_wide <- tibble(

  pop_2020 = c(37363, 168323, 60572),
  pop_2021 = c(37162, 169660, 60381),
  pop_2022 = c(36777, 170533, 59949)

pivot_longer(): Wide to Long

bea_long <- bea_wide |>
  pivot_longer(
    cols = starts_with("pop_"),
    names_to = "year",
    names_prefix = "pop_",
    values_to = "population"
  )

bea_long
# A tibble: 9 × 3
  county_name    year  population
  <chr>          <chr>      <dbl>
1 Addison, VT    2020       37363
2 Addison, VT    2021       37162
3 Addison, VT    2022       36777
4 Chittenden, VT 2020      168323

  • One row per county and year, instead of one row per county
  • Almost everything in dplyr and ggplot2 wants data in this shape

pivot_wider(): The Reverse

bea_long |>
  pivot_wider(names_from = year, values_from = population)
# A tibble: 3 × 4
  county_name    `2020` `2021` `2022`
  <chr>           <dbl>  <dbl>  <dbl>
1 Addison, VT     37363  37162  36777
2 Chittenden, VT 168323 169660 170533
3 Rutland, VT     60572  60381  59949
  • Takes values from one column and spreads them into new columns, one per unique value
  • Good for a summary table you want to read by eye, less useful once you need to filter or group by year again

Getting Data

Where Data Comes From

  • A file someone hands you, or you download: CSV, Excel, and the like
  • A live API (application programming interface) you query with code
  • A web page you scrape, when nothing else is available
  • R4DS Ch. 7-8 covers the first in depth. APIs and scraping are in R4DS Ch. 24, much further along in the book than we’ve gotten.
  • Reading files is readr’s job, the tidyverse package behind read_csv() and other similar functions

Reading Files, Revisited

read_csv(
  "data/hw2a.csv",
  skip = 3,
  na = c("", "NA", "(NA)", "N/A")
)
  • read_csv() is in HW2’s starter code
  • skip jumps past header rows a file doesn’t need, common in government exports
  • na tells readr which strings actually mean “missing.” This varies widely.
  • readr prints a column specification when it loads. Always glance at it. A date or number read in as text usually means a stray character snuck into that column.

Getting Data from an API

What’s an API?

  • Application programming interface: structured way to ask a website for data and get back something other than a webpage, usually JSON
  • You build a URL with your request baked in, and the server sends back data instead of a rendered page
  • Census, BLS, and BEA all publish APIs. Some want a free registration key, a few don’t.

Not Every API Is Free

  • There is an entire industry based around data for purchase. For example, you might want to get a drive distance from UVM campus to 500 different addresses in Vermont. You could get this for free by manually entering the addresses into Google Maps. Or you could give Google a single file with every address and have it calculate all 500 distances in a few minutes.
  • The catch: you have to pay! (a fraction of a penny for each, but it adds up).
  • If a private data provider gives you an API key, keep it secret or bad actors can drain your credits (or wallet) in a very short time.

A Live Example: the BLS API

library(jsonlite)

url <- "https://api.bls.gov/publicAPI/v1/timeseries/data/LNS14000000"
bls_raw <- fromJSON(url)
bls_raw

bls_raw$Results$series$data[[1]] |> head()
  • LNS14000000 is the BLS series ID for the national unemployment rate
  • No key needed for a request this small, heavier use wants a free one
  • fromJSON() already turned the nested JSON into data frames. We just have to dig through the list to find the one we want.
  • Read bls_raw$Results$series$data[[1]] left to right: start at bls_raw, step into $Results, then $series, then grab the first item out of the data list with [[1]]

Turning It Into a Tidy Data Frame

unemployment <- bls_raw$Results$series$data[[1]] |>
  as_tibble() |>
  select(year, period, value) |>
  mutate(value = as.numeric(value))

unemployment
  • $ and [[ ]] dig through the nested list until you hit the data frame you actually want
  • Watch value after the conversion: one row comes back NA, from the month of the 2025 government shutdown. Real missing data, not a mistake.
  • Week 8’s tidycensus wraps this same fetch-then-dig pattern, but for Census data specifically. It will become our friend.

Web Scraping: A Quick Look

library(rvest)

page <- read_html("https://en.wikipedia.org/wiki/List_of_counties_in_Vermont")
counties <- page |>
  html_element("table.wikitable") |>
  html_table()
  • Some data only exists inside a web page, with no file or API behind it
  • rvest reads a page’s HTML and pulls out a specific table or element
  • The process is fragile: if the page’s layout changes, your code breaks with no warning
  • Use it last, after checking for a file or an API. Read the site’s terms of service and robots.txt first, and never hit a server with rapid repeated requests, it can look like an attack and get you blocked.

Joins: Combining Two Data Frames

Why Joins

  • HW2 step 5 asks you to combine df and df2 using a shared column, county_fips
  • A join lines up rows from two tables using one or more shared columns, called keys (we will often refer to this as a “unique identifier”)
  • Nothing here is BEA-specific. Joins work the same way on any two data frames that share a key.

A Small Example

pop <- tibble(
  county_fips = c("50001", "50003", "50007"),
  county_name = c("Addison", "Bennington", "Chittenden"),
  population = c(37363, 34478, 168323)
)

income <- tibble(
  county_fips = c("50001", "50003", "50011"),
  income = c(58000, 52000, 71000)
)
  • Both tables share county_fips, the key
  • The counties don’t fully overlap: 50007 is only in pop, 50011 only in income

left_join(): Keep Everything on the Left

pop |> left_join(income, by = "county_fips")
# A tibble: 3 × 4
  county_fips county_name population income
  <chr>       <chr>            <dbl>  <dbl>
1 50001       Addison          37363  58000
2 50003       Bennington       34478  52000
3 50007       Chittenden      168323     NA
  • Every row of pop survives, matched or not
  • Chittenden (50007) has no match in income, so it gets NA
  • 50011’s income is dropped. It wasn’t in pop to begin with.

Other Join Types, Briefly

Join Keeps
left_join() Everything on the left, matched where possible
inner_join() Only rows that match in both
full_join() Everything from both, matched where possible

left_join() is the one you’ll reach for almost every time: you have a main table and you’re adding to it.

Watch Out: Duplicate Column Names

  • If both tables have a column with the same name that isn’t the key (both have county_name, say), the join keeps both and adds .x and .y suffixes
  • Two fixes:
    • select() away the extra column from one side before joining
    • Join on every shared column: by = c("county_fips", "county_name", "state")
