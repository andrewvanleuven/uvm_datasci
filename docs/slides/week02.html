dplyr, Part 1: Rows and Columns

How Every dplyr Verb Works

  • The first argument is always a data frame
  • The other arguments say what to do with it, using column names without quotes
  • The result is always a new data frame
  • The original is left unchanged. To keep a result, assign it with <-

The Pipe: |>

Read |> as “and then.”

# nested: read inside out
arrange(filter(midwest, state == "WI"), poptotal)

# piped: read top to bottom
midwest |>
  filter(state == "WI") |>
  arrange(poptotal)

To get |> instead of %>% (in RStudio on your machine), go to Tools → Global Options → Code and check Use native pipe operator. This is already enabled in Posit Cloud!

filter(): Comparisons

Operator Meaning
== equals (two = signs!)
!= does not equal
>, >=, <, <= greater/less than
&, | and, or
%in% matches any value in a list 
midwest |> filter(state == "MI" | state == "OH")
midwest |> filter(state %in% c("MI", "OH"))   # same thing, less typing

filter(): Mistakes Everyone Makes

midwest |> filter(state = "WI")          # one = sign
midwest |> filter(state == WI)           # forgot the quotes
midwest |> filter(state == "wi")         # capitalization matters
midwest |> filter(state == "WI" | "MI")  # has to be state == "MI"
  • The first one needs a double equals sign.
    • A single = sets something, like an argument (digits = 0) or a new column in mutate().
    • A double == asks a question, “is this equal to that?”, and answers TRUE or FALSE for every row. filter() needs the question
  • The last one looks like it should work, but R needs a full comparison on each side of |. Use %in% instead.

if_else(): Pick Between Two Values

if_else(inmetro == 1, "Metro", "Non-metro")
  • if_else() takes 3 arguments, in this order:
    • a condition: a test that’s TRUE or FALSE for each row
    • the value to use where the condition is TRUE
    • the value to use where the condition is FALSE
  • Here, R checks each county one at a time: if inmetro == 1 is TRUE, the new column gets "Metro"; if it’s FALSE, it gets "Non-metro"
  • You’ll also see base R’s ifelse() (no underscore) online. It works the same way, but if_else() is stricter and catches more mistakes

case_when(): More Than Two Outcomes

For reference

We won’t use case_when() again in class, but it’s here for when you need it.

midwest |>
  mutate(
    size = case_when(
      poptotal >= 100000 ~ "Large",
      poptotal >= 25000 ~ "Medium",
      .default = "Small"
    )
  ) |>
  count(size)
# A tibble: 3 × 2
  size       n
  <chr>  <int>
1 Large     85
2 Medium   198
3 Small    154
  • Each line is condition ~ value. Read the ~ as “then”
  • R checks the lines top to bottom for each row, and the first TRUE wins. That’s why "Medium" doesn’t need & poptotal < 100000
  • .default catches everything that didn’t match (another dot argument!)

Watch Out: Averaging Averages (or Percentages)

mean(percbelowpoverty) treats a county of 1,700 people the same as Cook County (5 million). To get the real state-wide rate, add up the people, then divide:

midwest |>
  group_by(state) |>
  summarize(
    poverty_rate = sum(poptotal * percbelowpoverty / 100) / sum(poptotal) * 100
  )
# A tibble: 5 × 2
  state poverty_rate
  <chr>        <dbl>
1 IL            11.9
2 IN            10.7
3 MI            13.1
4 OH            12.5
5 WI            10.7

Missing Values

  • Real data has gaps. In R, a missing value is NA
  • Any math with an NA in it returns NA, unless you tell R to skip them
mean(c(10, 20, NA))
[1] NA
mean(c(10, 20, NA), na.rm = TRUE)
[1] 15
  • midwest has no missing values, but your BEA data might. The HW2 ‘starter code’ handles most of it

Dropping Missing Values: is.na()

  • To drop rows with a missing value, use is.na(). The ! means “not”
town_income <- tibble(
  town = c("Burlington", "Montpelier", "St. Albans"),
  income = c(52000, NA, 61000)
)

town_income |> filter(!is.na(income))
# A tibble: 2 × 2
  town       income
  <chr>       <dbl>
1 Burlington  52000
2 St. Albans  61000
  • filter(income == NA) doesn’t work. Nothing is ever “equal to” a missing value, so always use is.na()

Code Style

Why Style Matters

  • You will read your code more often than you write it, and so will your NBRC teammates
  • R4DS Ch. 4 is the full guide. Here are the rules that matter most

A Few Rules (More Like Guidelines)

# hard to read
df2<-midwest|>filter(state=="WI",inmetro==0)|>mutate(PopK=poptotal/1000)

# easier
rural_wi <- midwest |>
  filter(state == "WI", inmetro == 0) |>
  mutate(pop_k = poptotal / 1000)
  • Names in snake_case, and names that describe the contents
  • Spaces around <-, ==, +, and after commas
  • One verb per line, with |> at the end of each line
  • Comments explain why, not what

Reading Error Messages

You see It usually means
could not find function "glimpse" You didn’t run library(tidyverse)
object 'midwst' not found A typo, or you never ran the chunk that created it
unexpected symbol A missing comma, parenthesis, or |>
We detected a named input You used = where you meant ==

Read the whole message. The answer is usually in there.
